For absolutely anyone

Imagine you only ever heard one side of every story.

Now imagine, instead, you invited two smart people who disagree into the room. One is fully convinced the idea is right. The other is fully convinced it's wrong. They go back and forth, round after round, each one forced to answer the other's best point — not just repeat their own. When they're done, a referee who hasn't taken a side the whole time tells you plainly who made the stronger case, how sure they are, and why.

That's this system. The "smart people" and the "referee" are AI agents instead of humans — but the reason it works is the same reason it works with humans: disagreement, done honestly, surfaces things a single confident voice tends to skip over.

Argues against it

Why this exists

A single AI answer has a habit of sounding sure of itself — whether or not it should.

Ask one model a loaded question and you get one confident-sounding paragraph. It might be right. It might be quietly one-sided. You have no easy way to tell which. Forcing a real disagreement — with a judge held to a strict bar before it can end the debate — trades that false confidence for something you can actually check.

What it actually does

How it actually runs

The whole thing is a loop with two exits.

Not a diagram of boxes and arrows — this is the real order of events, the same one the code follows.

  1. Round 0

    Clarity check

    Your topic gets scored. Below 0.72, you get 1–3 clarifying questions and a rewritten, debatable topic. At or above, it starts immediately.

  2. Round N

    Pro argues

    180–260 words, a clear thesis, and a direct answer to whatever Con said last round.

  3. Round N

    Con argues

    Same length, same rules, pointed the other way — attacking Pro's weakest assumption.

  4. Every 2 rounds

    Judge checkpoint

    Reads the full transcript so far. Picks a leader, states a confidence score, and can only end the debate if min-rounds is met and confidence ≥ 82%.

  5. Branch

    Not confident yet? Back to Pro.

    The loop repeats, up to a hard ceiling of rounds, so a genuinely close call doesn't run forever.

  6. Final

    Verdict + transcript.md

    Winner, confidence, reasoning, and a summary table — written to disk, not just printed and lost.

When to reach for it

It's a tool for close calls, not every question.

Reach for it when…

  • A decision is genuinely contested and the cost of being one-sided is high
  • You want a defensible, written record of both sides — not just a gut call
  • You're drafting a balanced report or brief for other people to review
  • An architecture or product bet could reasonably go either way

Skip it when…

  • You just need a fact — debating "what year was X founded" wastes rounds
  • You're brainstorming freely; adversarial framing narrows things too early
  • You need an answer in seconds, not the time for several rounds

Under the hood

For the technically curious.

A short, honest architecture breakdown — expand what's relevant to you.

Pro, Con, and Judge are nodes in a StateGraph. Con's node increments the round counter; a routing function sends the graph to the Judge every two rounds, otherwise back to Pro. The Judge's edge decides continue vs end.

ClarityAssessment and JudgeDecision are Pydantic models bound via with_structured_output, so clarity scores and verdicts come back typed and validated instead of parsed from free text.

Each agent's own prior turns are sent back to it as assistant messages; the opponent's and the judge's turns are sent as user messages. That's what makes rebuttals engage with what the other side actually said, instead of each side continuing its own monologue.

The judge can only stop the debate once round ≥ min_rounds and confidence ≥ 0.82. Both conditions are enforced in code after the model responds, not just requested in the prompt.

LLM calls retry up to three times with backoff. If a run still fails, everything gathered so far is written to a *_PARTIAL.md transcript before the error propagates — a flaky API call doesn't erase an in-progress debate.

Model, base URL, and API key are CLI flags / env vars, so it runs against OpenAI directly or any OpenAI-compatible endpoint, including a local LiteLLM proxy.

def get_temperature(current_round: int, max_rounds: int) -> float:
    """Higher temperature early, lower later."""
    progress = (current_round - 1) / max(max_rounds - 1, 1)
    temp = 0.85 - (progress * 0.55)
    return round(max(0.30, min(0.85, temp)), 2)
